## What 1.1 added (prod)

Real multi-layer `detectLang()`, replacing the `?lang=` placeholder: `?lang=`
→ `#LanguageToggle button` → `…/SitePages/fr/…` path → SP UI culture →
`<html lang>` → `en`. Late-toggle polling (20 × 250 ms). New `data-fr-html`
inline tier. JSDoc throughout. Console tracing.

## Fixed in 1.1.1 (dev)

- `const LOG_PREFIX` / `VERSION` at top level → second load threw a
  SyntaxError; moved inside the IIFE.
- Late toggle detection set `current` without firing `onChange` → bsp-forms,
  the Alpine `$t` store and script-rendered UI stayed in the old language.
  Now one `switchTo()` used by `setLang()` and late detection.
- `detectLang()` ran twice and started a polling loop per call. It is now
  side-effect free; the poll starts once, at init, after `window.intl` exists.
- Toggle reading inverted: **the toggle names the OTHER language** (confirmed
  by the user 2026-10-14) — `FR`/`Français` ⇒ page is `en`, `EN`/`English`
  ⇒ `fr`.
- French path was hard-coded to one site; now `/sitepages/fr(-xx)?/` on any
  site.
- An explicit `setLang()` (even to the current language) stops late detection
  from overriding it.
- `intl.version` exposed; version/date/doc-comment order made consistent.

Verified: scratch Node probe (21 checks; the imported 1.1 fails 11), demo.html
in a browser (FR load, toggle, second load, simulated late `#LanguageToggle`),
bsp-forms `dev/smoke.spec.js` 159/159.

## Fixed in 1.1.2 (dev) — Codex review, xo turn 16

- A second load reused nothing: it replaced `window.intl` with an empty
  instance (dictionaries and bsp-forms' one-time `onChange` subscription
  lost) and started a second poll. Now a second load keeps the first
  instance and calls its internal `__reload()`: re-detect for the page now
  showing (SPA navigation), switch if needed, re-arm the poll (never two).
  A reload clears the setLang() pin; `?lang=` still carries the choice.
- `<html lang>` is set at load, not only on the first full `apply()` —
  bsp-forms loads intl on demand and never calls `apply()`.
- One throwing `onChange` listener no longer skips the rest (errors logged).
- `?lang=friday` counted as French (cut to two letters before checking).
  `normLang()` accepts only whole tags (`fr`, `fr-CA`, …) — also used for SP
  culture and `<html lang>`.

Verified: probe 35/35 (1.1.1 fails the 10 new ones), demo.html in a browser
(incl. second load keeps the instance and the dictionary), bsp-forms smoke
159/159.

Known, accepted: detection step 5 reads `<html lang>`, which intl itself
writes — after an SPA navigation with no toggle, path or SP culture, the
previous page's language carries over. Same as 1.1 after any `apply()`.
